01

先分清这三个名字

SUITE

Terminal Workspace

整套发行包的名字。包含下面两个组件，不是第三个服务。

V1 · LAUNCHER

Terminal Jump

独立原生 App，管理命令，处理 URL，创建或定位 iTerm2 中的终端。

V2 · SIDEBAR

Terminal Sidebar

iTerm2 右侧的任务面板：层级、记录、终端关联、Markdown 导入导出。

共用命令，不共用任务界面。

两版共用命令配置。V2 修改或删除某个终端入口，也会影响 V1 和引用它的 URL。任务与记录保存在侧栏自己的任务库中。

它会做

  • 每一级节点关联自己的终端。
  • 保存配置，等你明确点击才执行。
  • 再次点击受管理的运行入口，定位已有 pane。
  • 将任务和记录导出为层级 Markdown。

它不会做

  • 自动录屏、读终端输出或采集 shell 历史。
  • 自动同步 Obsidian、云端或另一台电脑。
  • 自动接管你手动打开的 SSH 终端。
  • 把任务描述、Markdown 内容当指令执行。
02

安装与首次启动

换一台 Mac 也能重新安装。不需要相同用户名、旧电脑目录或原来的 Python 路径。

这是源码安装包，不是免环境的预编译 App。

需要 macOS 14+、Python 3.11+、iTerm2，以及首次编译所需的 Apple Command Line Tools。安装依赖需要联网；本说明网站自身不需要。

先准备四项环境

环境要求 / 操作说明
macOS14 或更新版本只面向 Mac，不是 Windows / Linux 安装包。
iTerm2放在 /Applications/iTerm.app这是标准安装位置，不是开发者个人路径。
Python3.11+；已有 Homebrew 可用 brew install python也可使用 Python 官方安装器，无须为此额外安装 Homebrew。
Command Line Toolsxcode-select --install等待系统安装结束，再运行本工具安装器。

  1. 解压整个发布包

    找到 Terminal-Workspace-1.0.0-macOS-source.zip，解压到普通本地目录。保留文件夹结构；本网站 ZIP 是说明文档，不代替应用安装包。

  2. 双击 Install.command

    安装器会检查环境、安装专用 Python 依赖、生成本机 App。不要使用 sudo。新安装是空任务、空命令，不导入示例。

  3. 开启 Python API 并授权

    打开 iTerm2 设置，搜索 Python API 并启用。首次脚本连接或 Apple Events 自动化请求，按系统提示批准必要访问；安装器不会替你绕过授权。

  4. 打开 Terminal Sidebar.app

    在当前用户的 ~/Applications/ 中打开它，任务面板显示在 iTerm2 右侧 Toolbelt。没有登录自启；需要时再打开 App。

想先检查，不安装？

在解压的应用发布包目录执行：

只读检查
python3 install.py --check

若 python3 仍指向旧解释器，请使用新 Python 的完整路径。安装器会根据当前电脑生成运行路径，不能把旧机器的已安装 App / venv 直接当便携包复制。

macOS 阻止打开，或者双击后提示缺少环境？

先确认包的来源可信，再使用系统提供的“打开”批准流程。也可在解压目录运行 bash Install.command。不要关闭系统安全检查或批量移除陌生文件的安全属性。依赖不全时按提示补齐，再重试。

安装后面板在哪里？会默认打开 Profiles 吗？

本实现注册的是右侧 Toolbelt 网页工具，不是左侧标签栏。显式打开 App 时展示侧栏，不主动启用 Profiles 工具。若没有窗口，注册过程可能创建一个 iTerm2 窗口；新终端使用 iTerm2 默认 profile，这与显示 Profiles 工具是两回事。

完整步骤与卸载说明：下载 INSTALL.md

05

按工作粒度，而不是按窗口组织

项目、阶段、任务、细小步骤都可以作为节点。每个节点可以拥有自己的终端和记录。

你要做什么如何操作行为说明
建项目目录添加任务 → 类型选“目录 / 项目”目录不计入待办数，没有完成复选框，但可关联终端。
继续细分使用节点的添加子级操作，或新建时选“上级节点”任务也可以有子级，不必先转成目录。
移动一棵树编辑节点 → 修改“上级节点”整个子树一起移动，不改变子级已有的终端关联。不能移动到自己的后代。
标记完成勾选任务复选框按节点独立完成，不是父级一勾全树自动完成。
寻找历史任务状态筛选改为“全部”或“已完成”默认是未完成，不要把筛选隐藏误认为数据丢失。
找记录或细粒度步骤搜索任意层级或记录可按祖先名称、节点标题和记录内容查找。
减少视觉干扰逐级展开 / 收起，或“展开全部 / 收起全部”只是显示状态；收起不会删除子级。

用记录保存“为什么”，不是保存终端输出

展开节点的 「工作记录」，输入结论、问题或下一步，再提交。记录是手动追加的纯文本，带时间；可以随 Markdown 导出。不会自动抓取终端历史，也不会执行记录中的命令。

一条有用的工作记录

本地检查已通过。下一步：在测试主机验证中文输出；确认无误后再复用同一个入口。

父级与子级的关联互相独立。

移动节点不会自动继承父级终端。你可以让多个节点明确关联同一个入口，也可以为一个很细的步骤创建独立入口。当前界面没有拖拽排序、回收站或单条记录删除按钮。

06

终端入口，是一份可复用的启动配置

保存一个入口，不等于马上打开终端。关联一个入口，也不等于建立 SSH 连接。

MODE 01

SSH + tmux

选择主机、session、可选 window。适合已存在会话，或希望打开时按条件创建。

MODE 02

SSH 远端多行指令

为同一远端编写启动脚本。适合显式设置环境、切换目录等高级场景。

MODE 03

本地 Shell 脚本

在本机通过 zsh 执行。可以填写本地工作目录，不经过 SSH。

新建 / 编辑时，关注这些字段

  • 入口名称：给自己看的标签，可以修改。
  • 链接 ID：URL 和任务关联使用的稳定标识；新建时可留空自动生成。编辑已有入口时固定，不因改标题而换 ID。
  • 本地工作目录：是 Mac 上的目录，不是远端目录；远端目录需要在远端脚本中显式切换。
  • 启动脚本：属于可执行代码，只保存你理解并信任的内容。

不用先离开任务编辑窗口

在“本级关联终端”下可以直接 「新建终端并关联」；选中已有入口后可 「编辑所选终端入口」。保存入口后回到原来的节点草稿，再保存任务即可。

修改入口不会重启正在运行的命令。

如果它已经运行，再点只会定位。需要验证新脚本时，应安全结束旧连接，再重新打开。对于仍有工作的 tmux，可以先 detach 再连接，不要为了刷新配置去停止远端任务。

四种操作，四条边界

操作写配置连远端 / 执行
保存任务 / 保存入口是否
读取 SSH 候选列表否否，只读本机配置
查询远端 tmux不创建入口是，发起只读 SSH 查询
打开入口 / 确认现在创建 session取决于操作是，属于明确执行操作

同一个命令 ID 才按受管理实例复用。多个不同 ID 即使配置了相同 tmux session，也可能各自打开本机终端。运行锁存在却找不到原 pane 时，程序会拒绝重复执行，而不是擅自接管其他窗口。

先分清：SSH 主机是“去哪台机器”，tmux session 是“进入哪组远端会话”。

从本机 config 选择

  1. 新建或编辑 SSH / tmux 入口时，打开“从本机 SSH 配置选择”。
  2. 选择一个别名，主机字段会自动填入；不会自动连接，也不会自动选第一台机器。
  3. 刚改过 ~/.ssh/config？点“重读 SSH 配置”。已填写的主机不会被覆盖。
  4. 列表没有你的目标时，仍可手动填写别名或 user@host。
虚构配置，仅用于理解语法
Host demo-dev
    HostName dev.example.invalid
    User demo

不要原样连接：.invalid 是示例地址。按你自己的服务器信息，在本机维护 SSH 配置和凭据；本工具不会替你写入它们。

为什么 config 里有，候选列表里却没有？

列表是安全的静态子集：读取具体 Host 别名和受支持的静态 Include，排除通配符、否定模式；不执行 Match exec、ssh -G 或 ProxyCommand。Match 条件下的 Include、动态变量等可能缺失。它不是完整的 OpenSSH 配置解释器；真正连接仍由系统 SSH 解析。

解析器有限额：递归深度 12、最多 128 文件、单文件 256 KiB、总读取预算 1 MiB。异常时显示提示，手动输入仍可用。

已存在的 session：直接 attach

选择主机，填写 session 名称。普通向导生成的核心行为如下；-u 用于明确 UTF-8 客户端模式：

示意 · 需要替换为真实主机和会话
ssh -t demo-dev 'tmux -u a -t workspace'

还不存在的 session：两种明确选择

打开时若不存在则创建

在向导勾选对应选项。保存只记录条件创建脚本；直到点击打开才检查 / 创建并连接。

现在创建远端 session

触发创建操作后核对主机和名称，在确认框明确确认。这会立即在服务器创建后台 tmux session。

填写 window 时，向导会生成选择窗口所需的附加脚本；相应创建选项需明确选择。session / window 名称限字母、数字、下划线和短横线，且不能以短横线开头。工具不会关闭或重命名现有 session，也不用 attach -d 踢掉其他客户端。

查询远端为什么可能失败？

“查询远端”不是纯本机动作，它会发起 SSH，但使用 BatchMode=yes，不弹密码或首次主机信任确认。应先在普通终端完成身份与主机校验。查询默认 tmux socket，不支持向导配置自定义 -L / -S；高级场景需要完整脚本。

外部技术参考（联网打开）：OpenSSH 配置手册 ↗ · tmux 手册 ↗。以目标机器实际版本为准。

导出：选格式，再选文件位置

  1. 点真实侧栏底部 「导出 Markdown」。
  2. 选择“清爽层级 Markdown”或“可回导 Markdown”。需要改名、移动后再导入，优先选回导版。
  3. 检查阅读预览；展开“查看 Markdown 源码”可查看具体内容。
  4. 点 「选择文件位置并保存…」，或保存到默认目录，也可复制 Markdown。

取消系统保存对话框不会写文件。导出使用不覆盖策略，已有同名文件会拒绝；选择新文件名。预览之后若任务变更，需要重新生成预览再保存。

导入：先看到影响，再确认

1选择文件 / 粘贴或读取当前 TODO.md
→
2预览变更新增、更新、未知入口
→
3确认导入只更新任务，不执行
导入不是“以文件替换整个任务库”。

文件中没出现的节点会保留，不会因为你删了 Markdown 中的一行就删掉真实任务。需要删除时，请在 UI 显式确认。但文件中出现的节点字段会更新：省略终端链接会解除关联；回导格式中的记录按文件替换，删掉记录内容会清空对应记录。

编辑意图推荐做法注意
改节点名称保留回导版 ts-node 中的 ID，只改文字阅读版按完整名称路径匹配，改名可能新增节点。
移动子树保留 ID，修改整棵子树的缩进先在预览确认新父级，不重复使用 ID。
编辑记录记录放在所属节点之后、子节点之前保留 ts-note 的 ID / 时间可准确往返。
关联终端使用 [终端](terminal-jump://open/入口ID)未知入口会提示，不会自动创建命令。
旧文件回导先导出当前版本、认真核对预览不是三方合并，旧内容可能覆盖同 ID 的新内容。
多大的 Markdown 可以导入？

网页文件选择限制约 240 KB，HTTP JSON 请求上限 256 KiB；转义后的请求也要满足限制。单次最多 5000 个节点，标题 300 字符、单条记录 20000 字符。大文档应拆分。能导出的大文件不代表一定能一次导回。

为什么普通段落或代码块没有变成任务？

解析器面向标题、列表缩进、任务框、终端链接和记录引用，不是任意 Markdown 到任务的转换器。普通段落和围栏代码会忽略；导入它们不会执行命令。

09

把入口放在你已经使用的笔记里

Obsidian 负责写作，Sidebar 负责组织，Terminal Jump 负责把你带回终端。

笔记中的 Markdown 链接
[打开开发终端](terminal-jump://open/demo-ssh)

先在本机创建 ID 为 demo-ssh 的入口，再把链接放入笔记。点击链接由 macOS 交给 Terminal Jump，查找本机配置并创建 / 定位终端；笔记软件可能要求确认打开外部应用。网站示例不会直接触发这类协议链接。

URL 携带的是 ID，不是任意命令。

把链接发给另一台电脑，不会顺带迁移 SSH 凭据、脚本和任务。另一台电脑需要安装应用、配置同 ID 的入口，且具备自己的 SSH 登录环境。不要分享本地网页服务地址中包含的访问令牌。

python3 install.py --todo "$HOME/Documents/My Notes/TODO.md"

已有文件内容不会覆盖。这个参数设置“读取当前 TODO.md”的来源和默认导出目录，不是实时双向同步。默认升级不传这个参数时保留原路径。全新安装默认来源为 ~/Documents/Terminal Workspace/TODO.md。

推荐的手动往返

  1. 在侧栏导出可回导版，保存到笔记目录，使用新文件名。
  2. 在 Obsidian 编辑文字、缩进和记录，保留隐藏的 ID 注释。
  3. 回侧栏选择该文件 → 预览 → 确认。不要同时在两边编辑同一节点后盲目覆盖。
  4. 要分享漂亮版本时再导出阅读版；它不适合充当完整备份。

删除任务、删除命令入口、停止远端会话，是三件完全不同的事。

真实操作会移除什么不会做什么
删除本级，保留子级本级节点及其记录；直接子级上移不会删终端入口或改子级终端关联
删除本级及所有子级整棵子树及全部记录不会修改原始 TODO 或历史导出文件
删除终端入口两版共享的命令配置项不会关闭已打开的终端、删除任务或远端 tmux

任务删除需要在编辑窗口点“删除此节点…”，检查范围、数量及受影响列表后确认。删除入口在“终端入口”页操作，先核对关联数量；原任务关联和外部 URL 会失效，需要重新关联或重新创建同 ID。

误删后的正确顺序

  1. 停止继续修改，先保留当前数据，避免二次覆盖。
  2. 有效任务删除前有独立备份 tasks.pre-delete-*.json；另有最近修改前的 tasks.json.bak。
  3. 优先从备份提取所需节点。整库回滚会丢掉备份之后的修改，不能当作普通撤销。
  4. 确需整库恢复时，先停服务、备份当前库，检查 JSON 与命令关联后再替换。不了解结构时交给维护者处理。
不要用示例 JSON 覆盖活动数据，也不要用 kill-server“清理”侧栏。

本工具没有回收站或一键撤销；网页的删除示意不是恢复工具。远端任务不属于侧栏清理范围。

11

把工具带走，不把旧电脑路径带走

“在新 Mac 安装”和“迁移自己的工作数据”要分开处理。

INSTALL

只安装工具

带源码 ZIP，在新 Mac 准备环境、解压、运行 Install.command。安装器使用新机器的 HOME 和 Python 路径；不需要旧用户名或目录。

MIGRATE

继续原来的工作

还需要安全迁移任务与命令，并在新机器配置 SSH、重新授权。发布 ZIP 只有虚构示例，不包含你的工作内容。

推荐：可检查的手动迁移

  1. 在旧机器留一份备份

    导出可回导 Markdown。另行保留任务 JSON 和共享命令配置的安全备份；不要将其放进公开的发行包。

  2. 在新机器重新安装

    不要直接复制旧 App、venv 或 runtime 缓存。启动路径与解释器会在新机器重新生成，首次授权也要重新完成。

  3. 先重建 / 审核命令与 SSH

    为关联入口保留同样的命令 ID。逐条检查本地 cwd、脚本中的绝对路径、主机别名和远端目录；个人脚本仍可能绑定旧环境。

  4. 预览导入任务

    选择回导 Markdown，核对更新与未知命令提示，再确认。先用安全的本地测试入口验证，不要把生产任务用来做安装测试。

熟悉数据结构，想做完整 JSON 迁移？

在两边停止 Sidebar、备份目标机器已有库，再检查和迁移 tasks.json 与 commands.json。只有在目标为空、结构兼容且你理解替换影响时才做整库复制；它不是合并操作。不要覆盖新机器的运行令牌 / runtime / venv；设置中的 TODO 路径按新环境重设。

同一台电脑升级

解压新版，再双击安装入口。默认保留已有 Terminal Jump App、任务、命令、令牌和 TODO 路径；更新 Sidebar 本机服务，不关闭 SSH / tmux 终端。需要显式重编译 V1 时，在应用包目录用 python3 install.py --upgrade-launcher。

没有承诺“任何 Mac 零环境、零报错”。

已做源码与隔离流程验证，但不是完整的新机、所有系统版本与架构兼容矩阵。专用 venv 若是旧 Python 创建的，需要先停服务，将旧 venv 重命名保留，再用受支持 Python 安装；不要删任务目录来解决依赖问题。

12

先定位哪一层，再解决问题

界面 → 本机服务 → iTerm2 → SSH → tmux。别把每个失败都归到同一个地方。

App 打开了，右侧没有任务面板
  1. 检查 iTerm2 Python API 已启用，并批准首次连接。
  2. 运行 ~/.local/bin/terminal-sidebar status 查看本机服务。
  3. 运行 ~/.local/bin/terminal-sidebar open 再注册 / 展示。
  4. 可先用 ~/.local/bin/terminal-sidebar browser 验证网页服务；能打开网页不代表 iTerm2 授权也正常。

不要公开浏览器中的私有服务 URL，其中含访问令牌。

“查询远端”失败，但我手动 SSH 能登录

后台查询不交互，普通登录可能依赖密码、首次信任确认或只在交互 shell 中设置的 PATH。先用普通终端完成可信主机校验与认证配置，再检查非交互环境能否找到 tmux。也核对主机、远端用户及默认 socket 是否一致。查询有连接与进程超时；不要绕过 host key 校验来修复。

为什么普通 ssh 会读取环境，一键连接却不一样？

ssh host 通常进入交互式登录 shell；ssh -t host 'command' 则请求远端执行命令。分配 TTY 不等于强制读取交互配置。zsh 的交互设置通常在 .zshrc，基础环境可按需放在 .zshenv；还要核对 ZDOTDIR 和启动选项。不同 shell 按自身规则处理。

优先在入口里显式设置必需环境，或由你维护账户级环境配置，不要自动修改共享 root 的启动文件。zsh 启动文件说明 ↗

脚本里写了 zsh，为什么后面的 tmux 没执行？

单独启动交互 zsh 后，父脚本要等它退出才继续，所以后面的 tmux 没机会立刻运行。不要把 zsh 单独放在 tmux 前；把必需的环境设置与 tmux 放在同一段明确的远端脚本中。若刻意调用 shell，需清楚选择执行模式。

设置 HOME 后仍在原目录；应该改服务器哪里？

export HOME=... 只改变环境变量，不自动切换目录。需要时显式 cd，并检查账户真实 HOME、权限与 ZDOTDIR。先用入口级脚本验证；如果要变成默认行为，应由账户所有者或管理员按服务器规范设置，不要盲目改共享账户或复制别人的路径。安装器不会修改远端启动文件。

中文在手动终端正常，点击入口却不显示

先核对入口包含 tmux -u；还要比较远端 locale、实际 tmux 客户端的 UTF-8 状态、终端字体与程序编码，不能只看 pane 里的 LANG。修改入口不会刷新已有连接：安全 detach 后重新打开，保留远端任务，不需要 kill-server。

改了启动命令，再点击为什么没变化？

受管理入口仍在运行时，再次点击只定位，不重跑。安全结束旧连接后再次点击。若出现“找不到原 pane”而拒绝重复执行，先确认原任务状态，不要随意删运行锁来强制重启。

保存或导入提示内容已变化 / 版本过期

其他窗口、V1 或 CLI 可能更新了任务 / 命令。刷新，重新核对内容并生成预览再保存。这是防覆盖保护，不应通过手工篡改 revision 绕过。

导出保存窗口没出现，或者提示文件已存在

切到前台检查系统对话框，也可以使用“保存到默认目录”。已有同名文件不会被覆盖，请换文件名。取消对话框不写文件；确认导出完成前不要删除源数据。

任务不见了 / Markdown 导入后出现重复节点

先把状态筛选改成“全部”，清空搜索并展开树。阅读版没有稳定 ID，改名或移动后可能被认为是新节点；需要精确往返时使用可回导版并保留 ID。旧文件回导可能覆盖新内容，务必先预览。

不经过界面，也可以工作

可执行文件在 ~/.local/bin/。没有加入 PATH 时，使用这里的完整写法。

命令行为
~/.local/bin/terminal-sidebar status查看服务是否运行。
~/.local/bin/terminal-sidebar start启动本机网页服务。
~/.local/bin/terminal-sidebar open启动服务并展示 iTerm2 侧栏。
~/.local/bin/terminal-sidebar browser在浏览器打开私有任务面板，不是本说明网站。
~/.local/bin/terminal-sidebar stop停止侧栏服务，不停止 V1 或远端 tmux。
~/.local/bin/terminal-jump list列出本机共享命令。
~/.local/bin/terminal-jump open demo-shell明确执行 / 定位 demo-shell 入口。
手动导出 / 导入 · 最后一条会写入任务库
~/.local/bin/terminal-sidebar export output.md
~/.local/bin/terminal-sidebar export roundtrip.md --format roundtrip
~/.local/bin/terminal-sidebar import input.md
~/.local/bin/terminal-sidebar import input.md --apply

import 默认只预览；带 --apply 才写入。执行时重新计算变更；CLI 更新之后，已打开的网页需要刷新。请逐条理解后执行，不要把这一组命令当作自动安装脚本。
